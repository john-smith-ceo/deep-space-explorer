# База объектов

Всё, что живёт в мире, описано данными, а не кодом. Движок не знает про
станцию МИР — он спрашивает каталог: «что уместно в этой системе?»

## Где что лежит

| Каталог | Что там |
|---|---|
| `src/data/` | **база**: светила, Солнечная система, объекты и правила их размещения |
| `src/settings/` | настройки: небо, полёт и прыжок, звук, вид светила |
| `src/core/` | ядро: генератор случайных чисел с сидом, словарь языков, холст |
| `src/engine/` | движок: мир, планеты, звёзды, полёт, связь, звук, рендер |
| `src/ui/` | интерфейс: HUD, панель состояния, радар, сводка, меню |

Правило разделения простое: **в `data` лежит то, что можно перечислить**
(классы светил, планеты Солнечной системы, станции), **в `settings` — то, чем
это настраивается** (плотность звёзд, дальность прыжка, громкость), **в
`engine` — то, что из этого делает картинку**.

## Как добавить объект

Дописать запись в `src/data/objects.js`. Больше ничего трогать не нужно.

```js
{
  id:"kepler-station",
  kind:"station",
  nameKey:"station.kepler",          // ключ словаря, не текст
  where:{ starClass:["G","K"], planetType:["ocean"], chance:.3 },
  comms:{ call:"KPL-9", freqKey:"comms.freq.v", modeKey:"comms.mode.v",
          power:12, orbitKm:1200, incl:28.5, crew:9, voice:"mir" }
}
```

Название задаётся **ключом словаря**, а не строкой: интерфейс двуязычный, и
объект, названный текстом, останется непереведённым.

## Правила размещения

Все поля `where` необязательны и проверяются вместе — объект появляется там,
где выполнено каждое условие.

| Поле | Смысл | Пример |
|---|---|---|
| `system` | только в этой системе | `"SOL"` |
| `notSystem` | где его точно нет | `["SOL"]` |
| `requiresStar` | только там, где есть светило | `true` |
| `starClass` | классы светила | `["G","K"]` |
| `planet` | нужна планета с таким именем | `"Земля"` |
| `planetType` | нужна планета такого типа | `["ocean","desert"]` |
| `minPlanets` / `maxPlanets` | сколько планет в системе | `3` |
| `chance` | доля систем, где встречается | `.25` |

`chance` не бросается заново при каждом заходе: жребий привязан к сиду
системы и идентификатору объекта. Одна и та же система всегда даёт один и тот
же ответ, и он не зависит от того, в каком порядке мы летали.

Так станция МИР описана одной строкой правил:

```js
where:{ system:"SOL", planet:"Земля" }
```

— только в Солнечной системе и только пока в ней есть Земля.

## Виды объектов

`kind` определяет, кто объект использует:

| Вид | Кто читает | Состояние |
|---|---|---|
| `station` | связь и сводка по системе | работает |
| `beacon` | навигация | задел |
| `wreck` | сводка, будущая добыча | задел |
| `anomaly` | сводка, события | задел |
| `ship` | встречи в системе | задел |

Новый вид добавляется так: запись в каталоге, обработчик в том модуле, кому
она нужна. Каталог остаётся общим, а движок — не осведомлённым о конкретных
именах.

## Что уже данные, а не код

- **классы светил** — `data/stars.js`: радиус, светимость, масса, вид диска;
- **Солнечная система** — `data/solar.js`: восемь планет настоящими числами;
- **типы планет** — `settings/world.js`, блок `PLANET.types`: цвета, полосы,
  атмосфера;
- **объекты** — `data/objects.js`.

Из них выводится всё остальное: температура планеты — из светимости и
расстояния, длина года — по третьему закону Кеплера, задержка связи — из
расстояния до станции.
